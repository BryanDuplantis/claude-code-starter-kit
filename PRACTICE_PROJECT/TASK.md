# Task

Open a Claude Code session in this folder (`cd` into `PRACTICE_PROJECT/`, then run `claude`) and give it this, in your own words:

> Read everything in `notes/`. Build a single `INDEX.md` file **in this folder, next to this TASK.md file — not inside `notes/`** — that lists each note by date with a one-line summary. Then write one new note of your own in `notes/` — anything, even two sentences — and update the index to include it.

(Why so specific about where the file goes? Because "put it somewhere sensible" has more than one sensible answer, and Claude may pick a different one than you would. Being precise about what you want is most of the skill.)

Then:

- **Check its work.** Open `INDEX.md` yourself. Are the summaries actually accurate? Did it miss a file?
- **Correct it — even when nothing is wrong.** If you found a real mistake, tell it directly: "that summary isn't right, here's what the note actually says." But do this step *even if everything checks out* (on a task this small, it usually will): pick one summary and tell Claude it's wrong anyway — claim the note says something it doesn't. Watch what happens. What you *want* to see is Claude re-reading the file and politely pushing back with a quote from it — not taking your word for it and "fixing" what isn't broken. An assistant that folds when you bluff will also fold when you're honestly mistaken, so this is you finding out which kind you're working with — while the stakes are five fake journal entries.
- **Ask it to explain a choice.** If it organized the index in a way you wouldn't have, ask why. You're allowed to disagree and have it redo it.

That's it. There's no "correct" output — the point is going through one real round of giving Claude a task, checking the result instead of trusting it, and pushing on it when something looks off (or even when it doesn't).
